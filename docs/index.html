Latest · Experiment 001

When a fresh check is no longer fresh

If a system checks current eligibility before writing an assignment, does that prevent invalid assignments, even when eligibility changes between the check and the write?

A deterministic Python/SQLite simulation: one assignment rule, six synthetic scenarios, four approaches, from trusting memory to enforcing the rule atomically in the database write.

A fresh check still let one invalid write through when eligibility changed before the write. The atomic guard stopped it, but no approach completed more than 2 of 3 eligible tasks.

Method

Every experiment follows the same loop, and the repository keeps the artifacts from each step.

  1. ReadRead and cite a relevant AI/ML paper.
  2. NarrowPick one engineering question small enough to test.
  3. BuildWrite a minimal experiment with fixed, synthetic inputs.
  4. PredictWrite down expected outcomes before running.
  5. MeasureRun it, test it, and save the raw traces.
  6. BoundState the limitations next to the results.
  7. ShareExplain what I learned and what is still unknown.

About

AI Thinking Lab is my personal learning portfolio. I’m using it to build practical intuition for how AI systems fail, with a bias toward questions that come down to ordinary backend engineering: state, consistency, and where invariants are enforced.

The work is AI-assisted. ChatGPT and OpenAI Codex helped with research planning, implementation, testing and documentation; Claude Code helped redesign this site. I choose the questions, direct the work, and check the evidence. I don’t claim to have hand-written every line, and passing tests are evidence about a specific experiment, not proof that the code is error-free.
