Research. Experiments. Evidence.

I read AI and ML research, pick out one engineering question I can actually test, and build a small experiment anyone can rerun. Each entry has the code, the tests, the recorded results, and a plain statement of what the evidence does and doesn’t show.

So far that means agent failures that turn out to be ordinary backend problems: stale state, and where a rule actually gets enforced.

Experiment 001 · September 2026

Stale memory and check-then-write

If a system checks a worker’s eligibility right before writing an assignment, can that check still be wrong by the time the write happens? And what actually prevents the bad write?

A small Python/SQLite simulation: 6 scenarios, 4 approaches, from trusting memory to putting the condition in the INSERT. No model involved.

Checking first still let one invalid write through. Putting the condition in the INSERT stopped it. No approach finished more than 2 of the 3 eligible tasks.

How I run these

I pick one question from a paper, build the smallest thing that can answer it, write the expected outcomes into the test fixtures, run it, and save the raw traces. The write-up says what the result does and doesn’t show. Each experiment folder has the code, tests, results and notes.

About

This is where I work through AI papers by building small things. I’m most interested in where agent reliability comes down to backend engineering.
